框架选型

四个候选方案对比

框架语言优点缺点适合场景
✅ Next.js 16TypeScript全栈、API Routes、热重载学习成本略高生产级 Web 应用
StreamlitPython极简、数据科学友好样式差、难定制快速原型 / 数据可视化
GradioPythonML Demo 一键发布UI 固定、扩展性差模型展示页
Flask + HTMLPython灵活、轻量前端需手写、无工具链简单 API 后端

选择 Next.js 的关键理由

🔒 安全
API Key 在服务端，不暴露给浏览器
⚡ 流式输出
内置 Web Streaming API，支持 SSE 实时渲染
🚀 部署
Vercel / 云效均可一键部署，Docker 兼容

系统架构

+----------------------------------------------------------+ | 浏览器（用户） | | PDF 文件上传 / 表单填写 --> Next.js 前端（React） | | SSE 流式接收 <-------------- 实时渲染进度 + Token | +-------------------------+--------------------------------+ | HTTPS POST / SSE +-------------------------v--------------------------------+ | Next.js API Routes（Node.js 服务端） | | | | POST /api/pdf-summary | | 1. 校验文件格式 & 大小（前 10MB） | | 2. pdf-parse 提取文字层（前 12000 字符） | | 3. 构建 Prompt -> 调用 Groq API（流式） | | 4. 逐 token 转发为 SSE 事件 | | | | POST /api/copy-writer | | 1. 校验必填字段 | | 2. 构建三风格 Prompt -> Groq API | | 3. 解析 JSON -> 返回三版文案 | +-------------------------+--------------------------------+ | HTTPS（OpenAI 兼容协议） +-------------------------v--------------------------------+ | Groq Cloud（AI 推理服务） | | 模型：llama-3.3-70b-versatile | | 速度：~500 token/s，免费配额 | +----------------------------------------------------------+
PDF 解析：pdf-parse@1.1.1，纯 Node 运行，无浏览器 API 依赖
错误处理：lib/api-error.ts 统一将 AI 错误翻译为中文建议

总结 & 后续

已知问题（TOP 3）

  • P1Groq 免费配额耗尽后无降级方案，功能完全不可用
  • P2扫描版 PDF（图片型）无法提取文字，需接入 OCR
  • P2超 12000 字文档只分析前半部分，需分段 Map-Reduce

下一步优化方向

  • 接入 OCR 支持扫描版 PDF
  • 配置 API Key 池自动切换
  • localStorage 持久化文案历史
  • 支持 Word / TXT 等更多格式
